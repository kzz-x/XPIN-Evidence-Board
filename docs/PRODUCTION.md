# V5 制作规范：防穿模、时序与摄影机

Agent 在 Node 中制作数据，不操作浏览器。入口为 `src/authoring.ts`；可直接处理用户的 Project JSON 或编译 SceneBrief。先读源并保留恢复点，按稳定 ID 修改；不要为修穿模重建整个作品。人类操作参见 [使用指南](USER-GUIDE.md)。

## 先搭静态空间，再设计动作

板面 Z=0，+Z 朝观众。纸的 `position.z` 是基面，不是纸顶；顶面还包含曲率。不要把重叠的两张纸写在同一 Z，也不要靠非常大的 Z 避免闪烁：那会导致脱离的投影和失真的空间层级。

有意叠放时，用 `surfaceAt(p,x,y)` 查询稳定纸面高度。需要完整抬放时可调用 `liftToSurface(p,id,0.015)`；它按物件足迹采样，只提高 Z，保留 XY、旋转、尺寸与 ID。它会修改传入对象，只能用于允许调整的物件；不能自动修改用户锁定的手工布局。

```ts
import { clone, liftToSurface, auditProduction, validateProject } from "../src/authoring";
const revised = clone(sourceProject);
// 前提：用户允许抬放这张新便签；下层布局已经完成。
liftToSurface(revised, "note-c", 0.015);
validateProject(revised);
const report = auditProduction(revised, 0.1);
if (report.issues.some(i => i.severity === "error")) {
  throw Error(JSON.stringify(report.issues));
}
// 输出到新文件，保留 sourceProject；不要将 evaluate 中间姿态写回源。
```

如果高度不合意，应调整构图、翘曲、覆盖范围或纸张顺序，再检查。`liftToSurface` 不是刚体落体求解器，不负责夹子形体／薄边碰撞。

## 端点与固定件

工具图钉使用 `hostId + local`，局部 XY 在宿主尺寸内，local.z 通常约 0.025–0.04。用 `pinWorld` 查看世界坐标，不要把世界坐标误写进 local。绳连接 Pin ID，不能连接 Item ID；背包中的独立图钉 Item 不是绳端点。

把钉放在可见的上层宿主上。被上层纸盖住的下层钉，不应通过强行把绳穿到表面来掩盖错误。绳中心线自动避让可见稳定纸面，保留两端精确锚点；纸面边缘、弯曲中的柔纸、夹子、绳间交叉仍要检查。`ropeHeights` 返回 97 个 Z 样本，属于渲染派生数据，不写入工程改变原 slack/bend/control。

夹子、胶带等独立 Item 尚无自动附着父级。纸在飞行时，夹子不会自动跟着飞。合理做法是让纸先停稳，再让固定件贴附；必须同步移动时，给各物件显式编排一致动作并逐时检查，不能假设 groupId 是动画父级。

## 编排节奏与可读性

每镜只承担一个主要信息：建立地点、阅读证据、发现关系、解释结论。先列一个时间表，再写 Action/Cue。时间为所属镜头内秒数；报告和 `evaluate` 用全故事秒数。

| 事件 | 一个可用的起点 |
|---|---|
| 相片／便签进入 | 1.8–2.5 秒，cinematic 或 smooth，淡化 0.65–0.9 |
| 固定件贴附 | 宿主停稳后约 0.1 秒再开始；0.5–1 秒，local 或 stationary |
| 拉绳 | 两端钉与宿主都完成后，再用 0.8–1.5 秒 grow |
| 标注 | 镜头到达后，用 1–2 秒 draw；不要让观众追着移动的文字读 |
| 阅读停留 | 关键纸面到位后至少留 1–2 秒；实际时长随字数／口播调整 |
| 退场 | 完成阅读后淡出；先收绳／标注，再移走宿主更清楚 |

没有入场轨道就从首帧可见。仅退场轨道从完整可见开始。不要同目标轨道重叠；不是叠加混合，最后开始的轨道会接管，可能跳变。画外方向按故事摄影机和作品画幅计算；旁观自由视角看见物件从侧面进入是正常的，不应改成自由视角坐标路径。

## 运镜应该帮助叙事

先 `makeShot` / `poseFor` 得到可读构图，再按需要修改完整 Pose。`target` 是观看与对焦目标；选在要读的文字／钉绳交汇附近。不要只提高焦距而保持过近距离，也不要把摄影机放进纸面后方。

- 一个镜头优先一种主运动。推近配证据揭示，沿绳配关系追踪，全览配结论；避免一边大幅横移一边快速推近和倾斜。
- 镜头尽量在 4–7 秒内完成一个信息段，倾斜通常从 0–8° 起步。极斜角仅用于短质感镜头；文字阅读镜头应接近正面。
- 初始 `Project.camera` 与首镜衔接；相邻镜头若距离／角度差太大，减小位移、延长时长或增加过渡。引擎当前连续插值，不是具备独立剪切模式的专业剪辑台。
- 优先 smoother 获得端点速度／加速度归零的停稳，或用 cinematic/glide 贝塞尔；moveFraction 默认 0.85 留出阅读。yaw/roll 走最短角，push/pan 的附加位移也按同一曲线收尾。仍需检查两镜之间的构图、遮挡、速度变化，算法不会替作者设计镜头。
- 首帧、到达前后、过渡中点、动作交叉点与尾帧都要检查。建议数据以 0.1–0.25 秒采样；关键帧画面不是连续视频验收。

自由编辑视角在 `editorView`，故事初始机位在 `camera`，每镜机位在 `shots[].camera`。不要把自由环视写回故事机位；人类只有按 `0`／勾摄影机才跟随机位。逐帧故事视频始终输出故事摄影机，现场录制记录当前观察画面。

## 景别、角度、光圈与焦点设计

Agent 制作分镜时应主动考虑多种景别、角度和焦点变化，并写入镜头表；不要交付全程同一正面角度、同一距离的推近。变化必须有叙事理由，不能随机倾斜或每镜都虚焦。

一个三段起点：先用稍远的斜侧全览建立空间（约 35–45mm、f/5.6–8），再用方向不同的中近景读关键纸面（约 45–65mm、f/4–5.6），最后用钉绳／纸边特写说明关系（约 65–90mm、f/2–2.8）。焦距变化时重新算距离和构图，不要仅换焦距导致裁切。

拉焦应该揭示新的信息：让前景钉或绳先清晰，再缓缓把焦点交到后方文字；或者反向把背景证据引向交汇点。先到达机位，再留 1–2 秒拉焦、留一段阅读；不要在快速移动中反复来回拉焦。小 f 数能强调主次，重要长文仍应保持足够清晰。

用 `shot.camera.fStop`、`camera.focusDistance`、`shot.focusPull` 原生编排。from/to 是沿摄影机视线的深度距离，不是世界 Z；对象深度可用 `distance - dot(objectPosition-target, cameraBack)` 估算，再用实际画面检查。固定机位的起点／终点距离宜接近物件的真实深度，小幅拉焦往往更自然。

镜头曲线、光圈和焦点字段详见 [SCENE-REFERENCE](SCENE-REFERENCE.md)。自动对焦不等于独立目标追踪，当前拉焦是两个距离之间的时间插值。实时景深仍不是路径追踪的光学求解，不能据此承诺离线电影渲染完成。

## 材质精修与素材

照片印相层和白边应有不同的反射，普通文件应保持干纸纤维，金属只在特定角度出现细划痕高光。不要把粗糙度全部降到 0 来表示高级；每种表面分别调整 roughness / fiberStrength / paperCurl，近景用真实高分辨率内容。

用侧光观察纸边、塑料头和金属弯曲，再从主机位检查文字与照片是否仍可读。程序微纹理能丰富表面，但不能替代高质量照片、扫描纸纹和专业模型；当前材质改善应按实际画面描述，不声称完全达到实拍。

## 原生安全检查与交接

```sh
npm run project -- validate new.project.json
npm run project -- inspect new.project.json inspect.json
npm run project -- audit new.project.json production-audit.json
npm run project -- sample new.project.json 2.5 frame-2.5.json
```

报告文件只新建。`audit` 发现 error 时仍保存报告，退出码为 2；只有 warning 为 0，命令／数据无效为 1。不要用一次非零退出当作报告丢失，也不要忽略错误继续标注作品通过。

| 报告代码 | 处理方向 |
|---|---|
| PAPER_SURFACE_INTERSECTION / ITEM_BELOW_BOARD | 调层间高度／覆盖／翘曲，或对允许调整的物件抬到表面 |
| PIN_HEAD_BURIED | 换上层宿主或重新安排遮挡关系 |
| CONNECTION_BEFORE_ANCHOR_READY | 推迟绳开始，检查端点和宿主的轨道完成时间 |
| CAMERA_SURFACE_COLLISION | 增加距离、提高目标或减小斜角 |
| FOCUS_PULL_OUTSIDE_SHOT | 缩短拉焦或延长镜头，避免焦点在切换前未到达 |
| CAMERA_EXTREME_ANGLE / CAMERA_FAST_TRANSITION | 确认创作意图，必要时缩短位移、延时或加过渡 |

默认间隔 0.25 秒；长故事最多约 480 个等间隔样本，另加入动作边界／中点。它不是连续碰撞、完整包围体或遮挡求解器，也不检查所有画面裁切；`renderValidated:false`、`continuousCollisionVerified:false` 必须保留。错误解决并不证明写实质感或最终视频通过。

交接给人类：新工程 JSON、保留的源文件、改动说明、inspect/audit、需要特别检查的时间点。纯 Node 当前不输出 PNG／MP4；最终像素由同一 WebGL2 工作台生成。若没有实际画面验收，应明确标为待播放检查，不虚构已渲染成果。

## 下一版建议

1. **可附着固定件与空间约束。** 真正的纸张／夹子／胶带父子关系，包围形体、动态纸边和绳间避让，放置时即时提示冲突。
2. **专业时间线与逐镜焦点。** 可拖 Action/Cue、空间路径切线、剪切／连续过渡、更多光学关键帧、构图安全区和镜头缩略图；延续已实现的逐镜光圈／拉焦。
3. **Agent 批量验收与高质量输出。** 原生渲染任务接口、自动关键帧联系表、GPU 累积采样及长视频流式写盘／恢复，分别量化画质、耗时与内存。
